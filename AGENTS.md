# Persistent project rules — The Closer Project Android

1. Read `CURSOR_ANDROID_MASTER_WORK_ORDER.md`, then `README_START_HERE.md`, before acting. Read completed book release fully when present.
2. The included `source/book_baseline` is a **v0.1 scope baseline**; it is not the finished book. Don't invent missing canonical chapters or call the app complete without an approved complete edition.
3. This project is standalone from unrelated projects, including any scavenger hunt.
4. Preserve all 108 baseline IDs and 13 parts, six intended signature sessions, all navigation categories, full reader-mode book text and integrated book-derived art. Future editions may add more IDs.
5. Source book text/content is separate from app-specific copy. Journal/private user data is a separate store with separate migration and never overwritten by content updates.
6. Two participant profiles + explicitly shared notes + dated session revisits are essential, not optional polish. Do not invent real couple memories or answers.
7. Android runs core functionality completely offline, without mandatory login/cloud/ads/analytics.
8. All future book editions go through validated ingestion/diff, impact-based agent delegation, idempotent migrations, staged activation, regression tests and non-destructive rollback.
9. User's private writings, backups, passwords, signing keys and artifacts must never be committed, logged, tracked, or published. Use fictional fixture data for tests.
10. App should be a mature, warm, sensual-when-appropriate, entertaining experience, not a clinical couples' workbook. Consent/pause/pass are straightforward and non-patronizing.
11. Flutter/Dart architecture, one source of truth for content IDs, one migration owner, independent QA, accessibility and actual on-device installation are required.
12. Track progress and handoffs in files, not just chat. Never declare finish based on screens without content and data survival tests.
13. Every app component claimed to work must have actual source, runtime behavior and/or test evidence. Every imported graphic must actually render in the Android build.
14. For every substantial task, report changed files, source book edition, tests run, results, blockers and next checkpoint. Continue batches where the environment supports it; do not falsely claim unattended background execution.
